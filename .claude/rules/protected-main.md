# Защищённая ветка `main` и Pull Request

Ветка **`main`** на GitHub **защищена**.

## Обязательный поток изменений кода / конфигов

1. `git fetch origin` и создание рабочей ветки от **`origin/main`** (например `feat/issue-NN-kratko`, `fix/issue-NN-…`).
2. Коммиты только в этой ветке; затем **`git push -u origin <ветка>`**.
3. Оформить **Pull Request в `main`**; слияние после ревью и прохождения проверок репозитория.

**Не** делайте `git push origin main` с локальными коммитами обходными путями — политика org — только через PR.

## Связка с задачей (issue)

- Работа по продукту ведётся от **GitHub Issue** в этом репозитории (`task.yml`): блок **Trace**, при необходимости **Companion** на `cookie-frontend`.
- В описании или заголовке PR указывайте связь с issue (например `Closes #NN` или `Refs #NN` — по принятому в команде виду закрытия).
- Если PR без issue невозможен по правилам команды — сначала создайте или обновите issue, затем ветку и PR.
